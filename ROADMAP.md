# Roadmap

This roadmap describes areas of focus, not delivery commitments or release dates. Priorities can
change as GitHub APIs, project needs, and contributor capacity change. Open issues are the source
for specific proposed work.

## Current focus

- Expand useful enterprise, organization, and repository coverage while keeping incomplete or
  inaccessible data distinct from a passing compliance result.
- Keep compliance checks understandable and extensible through manifests, policy, fixture-backed
  tests, and actionable remediation guidance.
- Improve the clarity and traceability of generated documentation, reports, and synchronized
  findings.
- Preserve least-privilege collection and clear documentation of permissions, data handling, and
  platform limitations.

## How work is prioritized

Maintainers consider user impact, correctness, GitHub API availability, compatibility, security,
and the effort required to validate a change. Good first issues are suitable for contributors who
want a bounded introduction; they are not a promise that a pull request will be accepted unchanged.
Discuss substantial proposals in an issue before starting implementation.

See [support boundaries](SUPPORT.md), [issue triage](docs/governance/maintainers.md), and
[recorded decisions](docs/decisions/README.md).
