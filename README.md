# GitHub Governance

GitHub Governance is an open-source community toolkit for documenting GitHub configuration and
evaluating it against customizable policies. It supports GitHub Enterprise Cloud enterprises,
standalone organizations, and personal accounts. Platform administrators, security teams, and
repository owners can use its findings to review configuration and prioritize improvements.

Use it to:

- Generate Markdown documentation of account, organization, repository, security, Actions, and
  CODEOWNERS configuration.
- Evaluate policy checks against collected data, without treating unavailable data as compliant.
- Report findings in a compliance report, GitHub issues, and SARIF code-scanning alerts.
- Add organization-specific policies, exemptions, and custom compliance checks.

See the [governance check catalog](docs/checks.md) for every built-in check and its defaults.

The project is a PowerShell 7.2+ module and GitHub Actions workflow. The collector uses a
read-only GitHub App; workflow permissions are separate and used to publish generated docs and
findings. Generated documentation can contain sensitive organization and repository metadata:
keep its repository private or internal.

The built-in checks are starting points, not proof of regulatory compliance. Results depend on the
configured policy, GitHub API coverage, and the App's access; unavailable data is not treated as a
pass. See [coverage and limitations](docs/repo/README.md#notes) and
[permissions](docs/configuration/reference/permissions.md).

The [CIS GitHub Benchmark](https://www.cisecurity.org/benchmark/software-supply-chain-security)
is a reference for reviewing GitHub security configurations and tailoring governance policies.
This project does not currently provide a version-specific CIS control mapping or claim complete
benchmark coverage or certification.

## Get started

Choose an [enterprise, organization, or personal account setup path](docs/repo/SETUP.md#choose-your-account-scope).
The [configuration handbook](docs/configuration/README.md) covers the GitHub App, workflow,
policy, and first run; the [repository guide](docs/repo/README.md) describes the outputs and checks.

The enterprise inventory and compliance report are generated by the workflow and appear under
`docs/enterprise/` after a documentation PR is merged, or after direct publication if configured.
They are not checked into a fresh clone.

## Run locally

Requires PowerShell 7.2+. Import the module and connect a GitHub App with the required read access;
see the [permissions reference](docs/configuration/reference/permissions.md).

```powershell
Import-Module ./src/GitHubGovernance/GitHubGovernance.psd1
Connect-GHGovernance -Enterprise $env:ENTERPRISE_SLUG `
    -AppClientId $env:GH_APP_CLIENT_ID `
    -AppPrivateKey $env:GH_APP_PRIVATE_KEY

try {
    Export-GHDocumentation -OutputPath ./docs/enterprise
}
finally {
    Disconnect-GHGovernance
}
```

For an organization or personal account, use `-Organization` or `-User` instead of `-Enterprise`.
For GHE.com, pass `-ApiBaseUrl` as described in the [setup guide](docs/configuration/03-setup.md).

## Validate changes

The offline validations and end-to-end smoke test use fixtures and do not require GitHub
credentials or network access:

```powershell
Install-Module Pester -RequiredVersion 5.7.1 -Scope CurrentUser
Invoke-Pester -Path ./tests/validation
pwsh ./tests/Invoke-SmokeTest.ps1
```
