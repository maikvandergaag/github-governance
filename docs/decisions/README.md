# Decision records

Decision records capture significant choices that affect architecture, supported behavior, or
contribution policy. They provide context for future changes; they do not replace the current
documentation.

Add a numbered Markdown file when a decision is consequential and likely to be revisited. Keep it
focused and include:

- **Status**: proposed, accepted, superseded, or rejected.
- **Date**: when the decision was made.
- **Context**: the problem and constraints.
- **Decision**: the selected approach.
- **Consequences**: benefits, trade-offs, and follow-up implications.

When replacing a decision, leave the original record in place and link the superseding record from
both files.
