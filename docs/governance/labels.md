# Issue labels

This catalog defines how labels are used on this repository. Labels aid triage; they do not
guarantee that work will be accepted or scheduled. Maintainers may adjust labels as project needs
change.

## Issue type and participation

| Label | Use |
| --- | --- |
| `bug` | A reproducible problem or regression. |
| `enhancement` | A proposed capability or behavior improvement. |
| `documentation` | A documentation-only improvement. |
| `question` | A request for clarification or usage help. |
| `accessibility` | An accessibility-related improvement. |
| `duplicate` | The issue duplicates existing work. Link the earlier issue. |
| `invalid` | The report is not actionable or does not describe a valid project issue. Explain why. |
| `wontfix` | The project will not pursue the request. Explain the decision when practical. |
| `good first issue` | A bounded issue suitable for a new contributor; not a promise of acceptance. |
| `help wanted` | Maintainers welcome community help on the issue. |

## Triage and priority

| Label | Use |
| --- | --- |
| `needs-triage` | The issue needs maintainer review to confirm scope, details, or routing. Remove once triaged. |
| `priority:high` | High user impact, urgency, or a blocker to supported use. |
| `priority:medium` | Meaningful improvement or defect without an immediate blocker. |
| `priority:low` | Limited impact or a lower-priority improvement. |

Use at most one priority label per issue. Priorities are relative and do not establish a schedule or
response-time commitment. Do not assign a priority solely because an issue has waited.

## Workflow-managed compliance labels

The compliance workflow manages `compliance`, `compliance:enterprise`, `compliance:org`,
`compliance:repo`, and `severity:high`, `severity:medium`, or `severity:low` on generated findings.
These labels describe automated findings, not the priority of a contributor issue. Avoid manually
changing them on workflow-managed issues; see [compliance issues](../repo/README.md#compliance-issues).
